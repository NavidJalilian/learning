When Nodes Die

2

Pass it on: gossip

Predict, then watch a crash get detected

The book's fix is a gossip protocol: servers spread news the way rumours spread in an office — tell a few people, who tell a few more.[1][3] Each server keeps a membership list: every member's ID plus its heartbeat counter — a number that member bumps by 1, over and over, to say "still alive".

  • Every tick, each server adds 1 to its own counter.
  • Each server sends its whole list to 2 random peers, who pass it on next tick.
  • On receipt, keep whichever counter is higher, and note when it last rose.
  • A counter that hasn't risen for 3 ticks (the timeout) makes that member a suspect.

Honest caveat — detection is a well-informed guess. The timeout is a dial: set it short and a slow server (say, one paused for memory clean-up) gets falsely declared dead; set it long and real crashes go unnoticed for longer.[3] And because gossip spreads randomly, every node learns the news eventually, not at one exact moment. Also, in this sim a rebooted server keeps counting from where it stopped; a real reboot starts again from zero, so Cassandra pairs the counter with a "generation" number (when the server started) to tell new heartbeats from old ones.[6]

3

Cover for a friend

Sloppy quorum + hinted handoff

Failure spotted. Now keep serving. Recall quorums (Quest 6.4): each key has N = 3 home servers — the first 3 you meet walking clockwise round the hash ring — and a write must be confirmed by W of them. A strict quorum only counts those home servers, so if too many are down, reads and writes get blocked.[1]

A sloppy quorum relaxes that: skip the dead servers and use the first W healthy servers clockwise for writes (first R for reads).[1][2] The stand-in keeps a hint — a note saying "this really belongs to s2" — and when s2 is back, it hands the data over and deletes its copy. That's hinted handoff. (In the book's picture, s2 is down and s3 covers for it.)

Here, cart:7 lives on s0, s1, s2. Settings: N=3, W=2, R=2. Predict each round, then watch.

Honest caveat — a sloppy quorum isn't really a quorum. W + R > N (2 + 2 > 3) normally guarantees a read overlaps the latest write. With a sloppy quorum the write may land on stand-ins outside the home servers, so a read can miss it entirely — exactly what you just saw. Dynamo accepts this for availability; Kleppmann calls a sloppy quorum "an assurance of durability", not a guarantee of fresh reads.[2][4] Hints are also best effort: Cassandra stops saving them once a server has been down for 3 hours (its default), and after that only a full repair can fix the replica.[7]

4

Spot the difference

Anti-entropy with Merkle trees

Hinted handoff covers short outages. But what if a disk dies, or the stand-in holding the hints crashes too? Then replicas have quietly drifted apart. The fix is anti-entropy: compare two replicas piece by piece and update each piece to the newest version.[1][2]

Comparing a billion keys one by one is hopeless. The trick is a Merkle tree (hash tree): every parent's label is the hash of its children, so one hash at the top sums up everything below it.[5] (A hash is a short fingerprint of some data: change one byte, and the fingerprint changes.) Honest caveat — the book's tree is simplified. In Dynamo, the leaves are hashes of individual keys, and each server keeps a separate tree per key range it holds. When servers join or leave, key ranges shift and those trees must be rebuilt — a real cost Dynamo calls out.[2] And with buckets, one changed key means re-sending its whole bucket, so the data moved tracks the differences, not the total.

Lights out + recall

Data-center outage, then the toolkit from memory

Last failure: the whole building. Power cuts, cooling failures, network outages and natural disasters can take out an entire data center.[2] The fix is blunt: replicate across data centers, so users can still reach their data when one site is completely offline.[1] Dynamo builds each key's replica list so the copies sit in more than one data center.[2]

🎓 Level-up note (for later)

Real systems moved past the book's simple timeout. Cassandra uses a "phi accrual" failure detector, which turns "how late is this heartbeat?" into a suspicion score instead of a yes/no.[6] And Dynamo itself dropped its cluster-wide failure view: each node just notices when a peer stops answering, and admins add or remove servers explicitly (§4.8.3).[2] Mentioning either one in an interview signals depth.
