Honest caveats. The minute ranges are the book's guide for a roughly 45-minute session; the game clock is our own framing, and real interviews vary. And ~20 requests per search assumes one request per character typed. Real search boxes usually debounce (wait for a short pause in typing before sending), so real traffic is lower. The book's number is a deliberately pessimistic upper bound.

    Honest caveats. (1) "O(1)" is only true because the prefix length is capped (around 50 characters) and each node stores its top k. It's bounded work, not magic, and it costs memory: a popular query is copied into the top-k list of every ancestor node. (2) With a weekly rebuild and a one-hour browser cache, a suggestion can be up to a week (plus an hour) out of date. Own that trade-off out loud. (3) Sampling 1 in N log lines keeps the popular queries but loses the rare ones.

    🎓 Level-up note
    
      The book's design is honest about being simple: popularity-only ranking, a weekly rebuild, prefix-only matching, letter-based shards. A senior candidate names each of these as a choice with a cost: suggestions up to a week (plus an hour of browser cache) stale, no "twin peak" for "peak", hot letters. Then say what you'd change if the requirements moved. Run this interview out loud once this week with a 45-minute timer and draw the two-lane diagram on paper from memory.
