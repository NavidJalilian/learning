Dig in

Step 3 · data model, code length, generation

The interviewer zooms in on four things, one at a time: what you store, how long the code is, how you make the code, and the exact step-by-step flows. Expect pushback: whatever you pick, she'll poke its weak spot.

🎓 Level-up note

Four places where the book's clean story meets real life. (1) Guessable codes. The book picks base 62 of a unique ID but doesn't spell out how to stop people guessing the next code. Have "scramble or randomise the ID, and rate-limit lookups" ready. (2) ID width. Seven characters only work if the ID generator hands out compact, counter-style numbers (a ticket server or blocks of IDs per server). A full 64-bit Snowflake ID (Ch. 7) encodes to 11 base-62 characters, not 7. (3) Headroom. 627 ≈ 3.5 trillion is only ~9.6× the 365 billion we need. Ten times the traffic means 8 characters. (4) 301 vs 302. Real shorteners mostly use 301 and still count clicks. Treat the book's split as an interview simplification.
