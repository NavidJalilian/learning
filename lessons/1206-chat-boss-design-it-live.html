Honest caveat: the cursor and the IDs don't quite fit. The book picks a local sequence number for message IDs: unique only inside one 1-on-1 chat or group. But it syncs devices with a single cur_max_message_id per device. If IDs restart in every channel, one number can't say "what I've seen" across all of them. A strong answer keeps a cursor per conversation on each device, or gives each user's inbox its own sequence.

Boss: the curveball barrage

Step 3 · "what happens when…?"

Now Maya stops nodding and starts poking holes. Seven curveballs from across the chapter. Each answer takes about 1.5 game-minutes. A wrong one costs a heart and an extra minute of backtracking.

Honest caveats from the curveballs. (1) The book's whole failure story is two lines: service discovery hands clients a new chat server, and messages are resent with "retry and queueing". Jittered backoff (each client waits a slightly random time before reconnecting) and dedupe by a client-made message ID are standard practice, but they go beyond the book. (2) Real chat stacks carry far more machinery: WhatsApp runs on Erlang, and Discord on Elixir with ScyllaDB[4]. Expect routing tables, rate limits and per-user sequences that a 45-minute sketch leaves out.

Honest caveat: end-to-end encryption changes more than the book says. WhatsApp uses the Signal protocol[6][7]. The server stores only ciphertext (scrambled bytes it has no key for). So server-side search, moderation and spam filtering get much harder. Multi-device sync gets harder too: the sender encrypts a separate copy for each of the recipient's devices.

🎓 Level-up note

The book's design is a sketch sized for a 45-minute interview. Run it out loud once this week: set a timer, draw the whiteboard on paper, and answer each curveball from stage 4 without looking. Three deeper points to have ready. (1) Storage products change; access patterns don't. See how Discord stores trillions of messages, bucketed by channel and time. (2) End-to-end encryption moves work to the clients. The WhatsApp white paper shows how multi-device works when the server can't read anything. (3) Service discovery is a real coordination service. ZooKeeper stores which chat servers are alive and how busy each one is.
