2

Chop by GOP

Cut the film where it's safe

A video is a stack of still pictures called frames, usually 24 to 60 a second. Storing every frame as a full picture would be huge, so encoders use three kinds of frame:[3]

  • I-frame (keyframe): a complete picture. It needs nothing else to be drawn.
  • P-frame: stores only what changed since an earlier frame.
  • B-frame: stores changes compared with frames both before and after it.

A GOP starts at an I-frame and runs until the next one. The book says the preprocessor splits the video stream into GOP-aligned chunks. Each chunk can be played on its own and is usually a few seconds long. The book adds that some old phones and browsers can't split a video by GOP before uploading, so the preprocessor does it for them on the server.[1]

Make 3 cuts so the 48-frame film becomes 4 chunks that each play on their own. Tap a frame to cut just before it, and tap it again to undo the cut.

Stage the DAG

Turn a graph into waves of work

The preprocessor builds the DAG from configuration files that client programmers write. The book's tiny example has just two tasks: download the input, then transcode it. The DAG scheduler then splits the graph into stages and puts each stage's tasks into the resource manager's task queue.[1]

The rule: tasks in the same stage don't depend on each other, so they can run side by side. A stage starts once everything it needs is ready. Here's a simple version of the DAG from Quest 14.3.

4

Run the resource manager

You are the task scheduler

The resource manager decides who does what. In the book it is three queues plus a task scheduler:[1]

  • Task queue: a priority queue of tasks waiting to run. A priority queue always hands out the most important item first, not the oldest.
  • Worker queue: a priority queue of how busy each worker is (its utilisation).
  • Running queue: which tasks are running right now, and which worker runs each one.

Different task workers do different jobs: encoders, thumbnail makers, watermarkers, mergers. You are the scheduler now. Each tick: tap the highest-priority task (on a tie, the older one, so the lower #), tap the least-busy worker of the right type, then press Run it. Six ticks by hand, then the autopilot takes over.

  1. Get the highest-priority task from the task queue
  2. Get the best worker for it from the worker queue
  3. Tell that worker to run the task
  4. Bind task + worker and put them in the running queue
  5. Remove the pair from the running queue when the task is done

Where does it live?

Temporary storage and the final output

While a video is being processed, its pieces need a home. The book uses more than one storage system for this. Which one depends on the data's type, size, how often it's read and how long it lives. Its examples: metadata is small and workers read it often, so cache it in memory. Video and audio go in blob storage (cheap storage for big files, like Amazon S3). When processing finishes, the temporary data is freed.[1]

The last box in the line is the encoded video itself, such as funny_720p.mp4. It isn't temporary. It goes to transcoded storage and then out to the CDN, as in Quest 14.2.

🎓 Level-up note (for later)

  • The three-queue resource manager is a teaching design. The book draws on SVE and a Weibo engineering talk for this pipeline. Real systems often use a general-purpose job scheduler or a managed batch or queue service instead of a custom one.
  • Retrying is only safe if tasks are idempotent. Idempotent means running the same task twice gives the same result. If a "dead" worker was only slow and finishes later, a retried encode must overwrite its chunk, not add a duplicate.
  • Chunk boundaries aren't free. Each chunk starts with a full I-frame, so more chunks means a slightly bigger file. Encoders often force keyframes at regular intervals to make clean, closed-GOP cut points.[3]
  • Priority needs a guard against starvation. If urgent jobs keep arriving, low-priority jobs (like that 3-hour lecture) may never run. Schedulers usually raise a task's priority the longer it waits.
