Honest caveats. Real uploaders usually split files by bytes (for example S3 multipart upload) and leave GOP-aware splitting to the server; the book's client-side GOP split is possible but less common. The book's DAG model comes from Facebook's streaming video engine, SVE[3]. Its three-queue resource manager is an illustration: real systems often use a general job scheduler or a cloud batch service instead.

Boss: the curveball barrage

Step 3 · "what happens when…?"

Now the interviewer stops nodding and starts poking holes. Nine curveballs, mixed from every quest in the chapter. A right answer takes 1.5 minutes. A wrong one costs a heart and an extra minute of backtracking. Handle at least 7 of 9 to win the round.

Honest caveats. Retrying a task on a new worker is only safe if tasks are idempotent: running them twice gives the same result. Promoting a database replica can lose the last few writes if replication was asynchronous. Message queues usually deliver at least once, so the completion handler may see the same event twice and must handle that safely. Pre-signed URLs are an S3 feature[4]; Azure calls them Shared Access Signatures.

🎓 Level-up note

The book covers upload and watch only. Real YouTube also has recommendations, search, comments, view counting and monetisation, and some interviewers will push into one of them. Name the scope out loud ("I'll treat search as out of scope unless you want it"). Then say it out loud once: set a 45-minute timer, draw the upload flow on paper, and answer every curveball from stage 4 without looking. Where you stall is what to review.
