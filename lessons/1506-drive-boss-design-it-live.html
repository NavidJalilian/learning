Boss: the curveball barrage

Step 3 · "what happens when…?"

Now Maya stops nodding and starts poking holes. Seven curveballs, drawn from the whole chapter. Each takes about 1.5 game-minutes. A wrong call costs a heart and an extra minute of backtracking.

Honest caveat: fixed blocks break on inserts. Delta sync with fixed 4 MB slices only works well when an edit overwrites bytes in place. Insert one byte near the start and every later block shifts, so every hash changes. rsync gets around this with a rolling checksum that finds matching blocks at any offset[4]. Many backup and dedup tools use content-defined chunking instead: block edges are placed where the bytes match a pattern, so an insert only disturbs the block it lands in. The "a million connections per machine" figure comes from Dropbox's 2012 scaling talk[6].

Wrap it up

Step 4 · the last 3–5 minutes

The book's summary: this design is highly consistent, uses little bandwidth and syncs fast. It has two flows, one that manages file metadata and one that syncs file content, plus a long-polling notification service that keeps clients up to date[1]. A strong close also weighs alternatives. 🎓 Level-up note

Clicking the right answer is not the same as saying it. Run this interview out loud once this week: set a 45-minute timer, draw the whiteboard on paper, and talk through every curveball from stage 4 without looking. Three deeper points to have ready: the book leaves out real-time co-editing (Google Docs style). That is a separate problem, see differential synchronization. Resumable uploads are a real API, see Google Drive's upload guide. Cold storage is cheap to keep but slow and costly to read back, see S3 Glacier's retrieval tiers.
